# Как работать с этим проектом

Текст рассчитан на то, что его целиком отдают нейросети-помощнику. Всё, что нужно
знать о проекте, здесь есть.

## Что это

Сайт автосервиса Evolution Car Service, 21 страница. Статика, никаких фреймворков
и сборщиков. Весь сайт генерируется двумя python-файлами:

- `build.py` — шаблон: шапка, подвал, блоки, микроразметка, `<head>`;
- `pages.py` — контент всех страниц, здесь правится текст;
- `site/` — собранный сайт, он же публикуется.

Пересборка: `python3 pages.py`. **Зависимостей нет** — хватает голого Python 3.
Pillow нужен только для `build_images.py` (пересжатие фотографий), для публикации
не требуется.

Репозиторий: `yura-web-create/evolution-car-service`, ветка `main`.
Сайт открывается по адресу `https://yura-web-create.github.io/evolution-car-service/`.

## Как устроена публикация

Push в `main` → GitHub Actions собирает сайт → выкладывает на GitHub Pages.
Обычно меньше минуты. Никаких серверов, ssh и ручной заливки.

```bash
git clone https://github.com/yura-web-create/evolution-car-service.git
cd evolution-car-service

# правки...

python3 pages.py
git add -A && git commit -m "что изменил" && git push
gh run watch          # следить за сборкой
```

Собранный `site/` намеренно лежит в репозитории — так публикация ни от чего
не зависит.

## Где что править

| Что | Где |
|---|---|
| текст страницы | `pages.py`, блок нужной страницы |

| скрипт и форма записи | `site/js/app.js` |

## Фотографии

21 кадр в едином стиле, исходники PNG лежат в `site/img-new/`.

Заменить кадр: положить свой снимок 4:3 под именем нужного слота (список слотов —
словарь `MAP` в начале `build_images.py`) и запустить:

```bash
pip install pillow
python3 build_images.py
```

Он обрежет под оба соотношения и закодирует все пять размеров в AVIF и WebP.

## Переезд на свой домен

Адрес сайта нигде не зашит — он берётся из переменной окружения:

```bash
SITE_URL=https://example.com INDEXABLE=1 python3 pages.py
```

Под новый адрес пересобираются канонические ссылки, Open Graph, карта сайта
и микроразметка.

`INDEXABLE=1` открывает сайт поисковикам. **Без него сайт собирается с
`noindex, nofollow` и `robots.txt` с `Disallow: /`** — так и задумано, пока он
живёт на служебном адресе GitHub Pages: незачем занимать выдачу черновиком.
Включать только когда сайт встанет на свой настоящий домен.

Чтобы адрес подставлялся сам при каждой публикации, он задаётся в
`.github/workflows/pages.yml`, переменная `SITE_URL` в шаге сборки.

## Три вещи, сделанные осознанно

Менять можно, но понимая зачем — иначе вернутся проблемы, которые уже решены.

**1. Размеры шрифта и отступы секций заданы ролями** в `:root` внутри
`site/css/style.css`: `--fs-display` → `--fs-title` → `--fs-section` → `--fs-sub` →
`--fs-card`, и `--section-major` / `--section-normal` / `--section-compact`.
На глаз ничего не подбирается. Уровень заголовка секции расставляется автоматически
при сборке, в `render_sections`: первая содержательная секция страницы — опорная
глава, служебные блоки из набора `COMPACT_HEAD` — компактные. Руками в `pages.py`
это не задаётся.

**2. Реакция на курсор — только у настоящих ссылок.** Карточка без `href`
не поднимается и не отбрасывает тень. Иначе посетитель наводит на то, что выглядит
нажимаемым, и ничего не происходит.

**3. Фотографии не анимируются при появлении**, и после события `load` скрипт
снимает отложенную загрузку со всех оставшихся кадров (`preloadRest()` в `app.js`,
низкий приоритет, при экономии трафика не запускается). Если вернуть анимацию
проявления или отложенную загрузку — при быстрой прокрутке снова полезут размытые
заглушки вместо фотографий. Это уже проходили.
