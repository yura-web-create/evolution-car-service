Этот файл можно целиком отдать нейросети-помощнику: здесь есть всё, что нужно
знать о проекте, чтобы начать его вести.

## Что это

Сайт автосервиса, 21 страница. Статика, никаких фреймворков и сборщиков.
Весь сайт генерируется двумя python-файлами:

- `build.py` — шаблон: шапка, подвал, блоки, микроразметка, `<head>`;
- `pages.py` — контент всех страниц, здесь правится текст;
- `site/` — собранный сайт, он же публикуется.

Пересборка: `python3 pages.py`. **Зависимостей нет** — хватает голого Python 3.
Pillow нужен только для `build_images.py` (пересжатие фотографий), для публикации
не требуется.

## Как работать

```bash
git clone https://github.com/yura-web-create/evolution-car-service.git
cd evolution-car-service

# правки...

python3 pages.py
git add -A && git commit -m "что изменил" && git push
```

Push в `main` запускает GitHub Actions: сайт собирается и выкладывается на Pages.
Обычно меньше минуты. Следить за сборкой: `gh run watch`.

Никаких серверов, ssh и ручной заливки — публикация только через push.

Собранный `site/` намеренно лежит в репозитории: так публикация ни от чего
не зависит.

## Где что править

| Что | Где |
|---|---|
| текст страницы | `pages.py`, блок нужной страницы |
| телефон, адрес, режим работы | константы в начале `build.py` |
| список услуг и марок | `SERVICES` и `BRANDS` в `build.py` — меняются сразу везде: меню, подвал, карточки, микроразметка |
| оформление | `site/css/style.css` |
| скрипт и форма записи | `site/js/app.js` |

## Фотографии

21 кадр в едином стиле, исходники PNG лежат в `site/img-new/`.
Показываются они нарезанными под нужные пропорции, в AVIF и WebP,
по пять размеров на кадр.

Заменить кадр: положить свой снимок 4:3 в `site/img-new/` под именем нужного слота
(список слотов — словарь `MAP` в начале `build_images.py`) и запустить:

```bash
pip install pillow
python3 build_images.py
```

Он обрежет под оба соотношения и закодирует все размеры.

## Переезд на свой домен

Адрес сайта нигде не зашит — он берётся из переменной окружения:

```bash
SITE_URL=https://example.com INDEXABLE=1 python3 pages.py
```

Под новый адрес пересобираются канонические ссылки, Open Graph, карта сайта
и микроразметка.

**Про `INDEXABLE`.** Сейчас сайт собирается с `noindex, nofollow` и `robots.txt`
с `Disallow: /` — он намеренно закрыт от поисковиков, пока живёт на служебном
адресе GitHub Pages. Причина: у владельца работает копия сайта на другом адресе,
и две одинаковых страницы в выдаче конкурировали бы друг с другом.

`INDEXABLE=1` открывает индексацию. Включать **только** когда сайт встанет
на свой настоящий домен.

Чтобы адрес и флаг подставлялись автоматически при каждой публикации, они задаются
в `.github/workflows/pages.yml`, в шаге сборки (`SITE_URL`, при переезде добавить
`INDEXABLE: '1'`).

## Три вещи, сделанные осознанно

Менять можно, но понимая зачем — иначе вернутся уже решённые проблемы.

**1. Размеры шрифта и отступы секций заданы ролями** в `:root` внутри
`site/css/style.css`: `--fs-display` → `--fs-title` → `--fs-section` → `--fs-sub` →
`--fs-card`, и `--section-major` / `--section-normal` / `--section-compact`.
На глаз ничего не подбирается.

Уровень заголовка секции расставляется **автоматически при сборке**,
в `render_sections`: первая содержательная секция страницы — опорная глава,
служебные блоки из набора `COMPACT_HEAD` — компактные. Руками в `pages.py`
это не задаётся.

**2. Реакция на курсор — только у настоящих ссылок.** Карточка без `href`
не поднимается и не отбрасывает тень. Иначе посетитель наводит на то, что выглядит
нажимаемым, и ничего не происходит.

**3. Фотографии не анимируются при появлении**, и после события `load` скрипт
снимает отложенную загрузку со всех оставшихся кадров (`preloadRest()` в `app.js`:
низкий приоритет, при включённой экономии трафика не запускается).

Если вернуть анимацию проявления или отложенную загрузку — при быстрой прокрутке
снова полезут размытые заглушки вместо фотографий. Это уже проходили: владелец
читал проявление кадра как «сайт долго грузится», хотя картинка была уже скачана.
