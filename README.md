# Evolution Car Service — сайт

Сайт публикуется на GitHub Pages: https://yura-web-create.github.io/evolution-car-service/

## Как устроено

Статика, 21 страница, генерируется двумя python-файлами. Никаких зависимостей, никакой сборки.

- `build.py` — шаблон: шапка, подвал, блоки (герой, карточки, сплит, этапы, кейсы,
  FAQ, форма, карта), микроразметка schema.org, генерация `<head>`.
- `pages.py` — контент всех 21 страницы. Здесь правится текст.
- `imgdims.json` — размеры картинок, чтобы проставлять width/height (без скачков вёрстки).
- `build_images.py` — нарезка фотографий из `site/img-new/` во все размеры и форматы.
- `site/` — готовый сайт, его и заливаем.
- `fetch_images.py` — от прежнего подхода со стоками с Unsplash. Сейчас не используется,
  оставлен на случай, если понадобится добрать кадр из банка.

## Пересобрать и опубликовать

```bash
python3 pages.py
git add -A && git commit -m "что изменил" && git push
```

Всё. Дальше GitHub Actions сам соберёт сайт под адрес Pages и выложит его —
обычно меньше минуты. Следить за сборкой: `gh run watch`.

Собранный `site/` намеренно лежит в репозитории: так публикация не зависит
ни от чего, кроме голого Python 3.

## Правки

- Текст страницы — `pages.py`, блок нужной страницы.
- Телефон, адрес, режим работы — константы в начале `build.py`.
- Список услуг и марок — `SERVICES` и `BRANDS` в `build.py` (меняются сразу везде:
  меню, подвал, карточки, микроразметка).
- Оформление — `site/css/style.css`.
- Анимации и форма — `site/js/app.js`.

## Картинки

21 кадр, сгенерированный нейросетью в одном визуальном языке. Исходники — PNG 4:3
в `site/img-new/`. Каждый нарезан под пропорции, в которых реально показывается,
и лежит в двух форматах:

- `имя-box-640/1000/1600.avif|webp` — 4:3, для первого экрана и блоков со сплитом;
- `имя-card-640/1000.avif|webp` — 16:10, для карточек услуг и кейсов.

Браузер сам берёт AVIF, если умеет (примерно вдвое легче WebP), иначе WebP.
Обрезка под нужное соотношение важнее формата: до неё карточка 16:10 качала
вертикальное фото 2:3 и обрезала его на лету — 145 КБ вместо 37 КБ.

Пока фото грузится, в его месте показывается размытое превью 20 пикселей шириной —
оно вшито прямо в `css/style.css` (все 23 штуки весят 3,7 КБ). Никакой белой дыры при прокрутке.

**Заменить фото на свои:**

1. положить снимок в `site/img-new/` под именем нужного слота (список слотов —
   словарь `MAP` в начале `build_images.py`), формат PNG или JPEG, пропорции 4:3;
2. `python3 build_images.py` — обрежет под оба соотношения и закодирует
   все пять размеров в AVIF и WebP;
3. пересобрать превью-заглушки и вклеить их в стили:

```bash
python3 -c "
from PIL import Image, ImageFilter
import base64, glob, os, io
rows=[]
for f in sorted(glob.glob('site/img/*-box-640.webp')):
    n=os.path.basename(f).replace('-box-640.webp','')
    im=Image.open(f).convert('RGB'); w=20; h=max(1,round(im.height*w/im.width))
    im=im.resize((w,h), Image.LANCZOS).filter(ImageFilter.GaussianBlur(0.6))
    b=io.BytesIO(); im.save(b,'WEBP',quality=45,method=6)
    rows.append('.ph-%s{background-image:url(data:image/webp;base64,%s)}' % (n, base64.b64encode(b.getvalue()).decode()))
p='site/css/style.css'; s=open(p).read()
m='\n/* заглушки под фото — показываются, пока грузится картинка */\n'
open(p,'w').write((s[:s.index(m)] if m in s else s) + m + '\n'.join(rows) + '\n')
"
```

**Осторожно с удалением старых файлов.** Маска `*-640.avif` цепляет и `имя-card-640.avif`,
и `имя-box-640.avif`. Удалять только по полному шаблону.

## Графика

Всей графики на сайте — только фотографии и мелкие интерфейсные иконки (стрелки,
значки услуг). Рисованных иллюстраций нет: пробовали, выглядело кустарно, убрали.

Блоки, где графика несёт смысл:

- `showcase` — крупное фото плюс пронумерованный список направлений (блок «Работаем
  с автомобилем целиком»). Фото задаётся ключом `img`, список — `items`;
- `photocards` — карточки с фотографией-шапкой для произвольных пунктов;
- `gallery` — бегущая лента фотографий, кадры перечислены в `GALLERY_SHOTS` в `pages.py`.

## Форма записи

Бэкенда нет. Форма собирает сообщение и открывает WhatsApp с готовым текстом —
клиенту остаётся нажать «отправить». Ничего не хранится и никуда не уходит.

## Проверки перед сдачей

Всё это гоняется по живому сайту, а не «на глаз».

**Кадрирование фото.** Собрать контактные листы всех кадров в обеих пропорциях
и просмотреть: `card` 16:10 для карточек, `box` 4:3 для героев и сплитов.
Обрезка центральная, со смещением к верху кадра (`crop_resize` в `build_images.py`) —
пол в кадре менее ценен, чем то, что над ним.

**Марки на фото.** На странице марки не должно быть фотографии чужого бренда.
Проверять глазами: `grep -o 'ph-[a-z-]*' site/<марка>.html | head`.

**Баланс колонок.** В браузере, через iframe шириной 1280, сравнить высоту
`.split__body` и `.split__media`: разница больше 110 пикселей — колонка пустует,
надо добавить содержания.

**Рваные сетки.** Число карточек должно делиться на число колонок. Где не делится —
либо добить карточкой («Другая задача», «Другая марка»), либо сменить число колонок,
либо растянуть последний элемент (`steps--fill`).

**Адаптив.** Прогон на 360, 768 и 1024: `document.scrollWidth` не должен превышать
ширину экрана, и ни один элемент не должен вылезать за неё (кроме лент с прокруткой:
`.ticker`, `.gal`, `.hero__facts`).

**Статика.** Один `h1` на страницу, нет дублей `id`, у всех картинок `alt` и размеры,
`title` до 65 символов, `description` 110–178, JSON-LD парсится, нет битых ссылок
и отсутствующих файлов.

## Дизайн-система

Размеры шрифта и отступы секций заданы ролями в `:root` внутри `site/css/style.css`,
на глаз ничего не подбирается:

- `--fs-display` → `--fs-title` → `--fs-section` → `--fs-sub` → `--fs-card`;
- `--section-major` / `--section-normal` / `--section-compact`.

Уровень заголовка расставляется автоматически при сборке, в `render_sections`:
первая содержательная секция страницы — опорная глава (`sec-head--major`),
служебные блоки из набора `COMPACT_HEAD` — компактные. Руками в `pages.py`
это задавать не нужно.

Радиусы: карточки 14 px, фотографии 16 px, крупные плашки и CTA 20 px.

**Реакция на курсор — только у настоящих ссылок.** Карточка без `href` не поднимается
и не отбрасывает тень: иначе посетитель жмёт на то, что не нажимается.

## Загрузка фотографий

Первые 6 кадров страницы грузятся сразу (`EAGER_FIRST` в `build.py`), остальные —
отложенно. Но `preloadRest()` в `app.js` снимает отложенность со всех оставшихся
сразу после события `load`, с низким приоритетом. Иначе при быстрой прокрутке
отложенная загрузка не успевает и вместо фотографии видно размытую заглушку.
При включённой экономии трафика и на 2G догрузка не запускается.

Фотографии **не анимируются** при появлении. Проявление кадра читается как
«сайт долго грузится», даже когда он уже скачан.

## Переезд на свой домен

Адрес сайта нигде не зашит в коде — он берётся из переменной окружения:

```bash
SITE_URL=https://example.com INDEXABLE=1 python3 pages.py
```

Под новый адрес пересобираются канонические ссылки, Open Graph, карта сайта
и микроразметка.

`INDEXABLE=1` открывает сайт поисковикам. **Без него сайт собирается с
`noindex, nofollow` и `robots.txt` с `Disallow: /`** — так и задумано, пока он
живёт на служебном адресе Pages: незачем занимать выдачу черновиком. Включать
только когда сайт встал на свой настоящий домен.

Чтобы адрес подставлялся сам при каждой публикации, он задаётся в
`.github/workflows/pages.yml` — переменная `SITE_URL` в шаге сборки.
